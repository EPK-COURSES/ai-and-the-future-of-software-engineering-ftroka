# Personal Reflection

After researching career strategy and continuous learning in the AI era, I understood that software engineering is no longer only about learning one programming language or one framework. Technology is changing very quickly, and AI tools are becoming part of the daily work of developers. This made me realize that a software engineer must always be ready to learn, adapt, and improve.

What surprised me most is how fast AI tools can support developers. They can generate code, explain errors, suggest solutions, help with documentation, and even support testing. At first, this seems very positive because it can save time and make learning easier. However, I also understood that AI can become dangerous if a developer uses it without understanding. If someone only copies AI-generated code, they may finish tasks faster, but they may not develop real problem-solving skills.

My biggest concern is that students and junior developers may become too dependent on AI. A junior developer should learn how to debug, test, read documentation, understand requirements, and explain technical decisions. If AI is used as a shortcut instead of a learning tool, the developer may become weaker in the long term. In real software projects, it is not enough to have code that works once. The code must be secure, readable, maintainable, and suitable for the real problem.

At the same time, I see many opportunities. AI can help me learn faster by explaining difficult concepts, giving examples, comparing solutions, and helping me understand code written by other developers. It can also help me organize my learning process. For example, if I do not understand a topic such as APIs, databases, testing, or system design, I can use AI to get explanations and examples. However, I should still practice by myself and verify the answers.

This assignment also changed the way I think about career strategy. Before, I thought that learning new technologies was mostly about choosing a programming language or framework. Now I understand that a good career strategy should include fundamentals, real projects, portfolio development, communication skills, teamwork, and continuous learning. Technologies may change, but strong fundamentals remain useful for a long time.

I also understood that certificates can be helpful, but they are not enough alone. A certificate can show that someone studied a topic, but real projects show that the person can apply knowledge in practice. For this reason, I think building a GitHub portfolio is very important. A good portfolio should not only contain final code, but also README files, screenshots, explanations, diagrams, testing information, and commit history. This can show how I think and how I improve my work.

Another important point for me is open-source participation. Even small contributions can help a student learn from real projects. Reading other people’s code, fixing small issues, improving documentation, or understanding how teams collaborate can improve both technical and communication skills. In the future, I want to become more comfortable with reading existing code, not only writing new code from zero.

The skills that I think will remain important are problem solving, critical thinking, communication, teamwork, testing, system design, and ethical responsibility. AI can help generate code, but it cannot fully replace human judgment. A software engineer must understand the user’s needs, the business context, security risks, and the long-term impact of technical decisions. These are human responsibilities.

Personally, I will adapt by using AI as a support tool, not as a shortcut. I want to use AI to explain difficult topics, help me compare solutions, and improve my learning speed. However, I will continue practicing coding, debugging, testing, reading documentation, and building real projects. My goal is not only to know how to use AI tools, but to become a better software engineer with or without AI.

After completing this assignment, my opinion changed. I now see AI not as something that simply replaces developers, but as something that changes what developers must become. The future software engineer should be able to work with AI, but also question it, verify it, and improve its output. For me, continuous learning means practicing step by step, staying curious, and not depending fully on any tool.
